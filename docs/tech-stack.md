# K-Spot Trail 기술 스택 추천

> 기준 문서: [PRD v0.3](PRD.md) (10. 기술 스택 안, 11. 개발 단계) / 작성일: 2026-10-07
> 전제: 사이드 프로젝트(JWED와 병행), iOS + Android, 1차는 로그인 없음, 성지 20곳 내외로 시작
> 상태: **추천안**. 확정된 것은 백엔드 버전(Spring Boot 4.1.1 + Java 25)과 모바일 프레임워크(Expo)이고, 나머지는 확정 전입니다. 확정 여부는 [decisions.md](decisions.md)에서 관리합니다.
> 이 문서가 PRD 10번 "기술 스택 (안)"을 대체합니다.

## 결론 한 줄

**초안의 큰 틀(Expo + Spring Boot + MySQL + AWS)은 그대로 유지하고, 사이드 프로젝트 시간에 맞게 "운영 부담"만 줄이는 쪽으로 몇 군데 바꾸는 것을 추천합니다.**

PRD의 기능은 대부분 "정해진 데이터를 읽어서 보여주기"이고, 서버에 쓰는 것은 후기(F-08)뿐입니다. 그래서 특별히 무거운 기술이 필요한 기능은 없고, 승부처는 기술보다 **데이터 조사·검증**(PRD 13번 리스크 1순위)입니다. 스택은 익숙하고 손이 덜 가는 쪽이 정답입니다.

## 유지하는 것과 이유

### 1. 모바일: Expo 유지 (Flutter 대신)
- PRD 기능 중 Flutter가 더 유리한 것이 없습니다. 지도, 외부 앱 열기, 위치, 로컬 저장 모두 Expo에서 기본 지원됩니다.
- **1단계 완료 기준("폰에서 동작")을 가장 빨리 달성**할 수 있습니다. Expo Go 앱으로 QR만 찍으면 실기기에서 바로 확인되고, 맥이 없어도 iOS 테스트가 됩니다.
- 스토어 출시나 친구 5명 테스트(성공 지표)는 EAS Build로 처리할 수 있습니다.
- 예외: React/JS 경험이 전혀 없고 Dart를 이미 써봤다면 Flutter도 똑같이 괜찮습니다. 판단 기준은 기능이 아니라 "이미 익숙한 쪽"입니다.

### 2. 지도: react-native-maps 유지
- 마커 표시 + 필터 + 상세로 이동이 전부라서 충분합니다. 길찾기는 외부 앱이 하므로 지도 SDK의 길찾기 기능이 필요 없습니다.
- 네이버 지도 SDK는 국내 지도 품질은 좋지만 별도 네이티브 빌드와 네이버 클라우드 계정이 필요하고, 타깃(외국인)은 구글 지도에 더 익숙합니다. MVP에서는 쓰지 않는 것을 추천합니다.
- 주의: Android 정식 빌드에서는 Google Maps API 키가 필요합니다 (Expo Go에서는 키 없이 개발 가능).
- 참고: 한국에서는 구글 지도의 도보·자동차 길찾기가 제한적이고 대중교통은 됩니다. 그래서 F-05에서 **구글/네이버 둘 다 선택지로 주는 PRD 방향이 맞습니다.**

### 3. 백엔드: Spring Boot 유지 (버전은 JWED와 같은 4.1.x)
- PRD 초안의 "Spring Boot 3"은 특별한 이유가 있는 선택이 아니었습니다. JWED에서 4.1.1을 쓰고 있으니 같은 버전으로 맞추면 설정·의존성·코드를 그대로 가져다 쓸 수 있고(Java도 JWED와 같은 25 LTS), 3.x는 무료 지원 기간도 끝나 가는(또는 끝난) 라인이라 새로 시작할 이유가 없습니다.
- PRD에 "지난번 관광 앱의 Attraction, Review 구조를 이어 쓸 수 있다"고 되어 있어 이미 익숙한 스택으로 보입니다. 새로 배우는 비용이 0입니다.
- 성공 지표에 "AWS에서 24시간 이상 안정 동작"이 있어서, 백엔드·배포 경험 자체가 목표의 일부입니다. 포트폴리오로도 설명하기 좋습니다.
- 대안 비교: Supabase/Firebase 같은 BaaS를 쓰면 2~3단계가 훨씬 짧아지지만, Spring·AWS 경험이라는 목표가 사라집니다. **팀 질문 3번(스토어 출시 vs 포트폴리오)의 답이 "빨리 출시"라면** 이 대안을 다시 검토할 만합니다.

## 바꾸거나 추가하는 것과 이유

### 1. 1단계 더미 데이터를 "API 응답 모양 그대로"의 JSON으로
- 앱에 내장하는 더미 데이터를 PRD의 API 응답 형태(`/api/contents/{id}/spots` 등)와 똑같은 JSON으로 만들어 두면, 2단계에서 데이터 출처만 로컬 파일 → API로 바꾸면 됩니다.
- 앱 코드에서 데이터 접근을 `api/` 같은 한 곳에 모아 두는 것이 핵심입니다.

### 2. 성지 데이터는 Flyway 시드 파일로 관리 (관리자 화면 만들지 않기)
- 데이터가 20곳 내외이고 직접 조사·검증해서 넣는 구조라, 관리자 페이지를 만드는 것은 사이드 프로젝트에서 낭비입니다.
- 스키마와 성지 데이터를 Flyway SQL 파일로 Git에 두면 **누가 언제 어떤 출처로 수정했는지가 커밋 기록으로 남아** PRD의 "출처·최종 확인일" 원칙과도 맞습니다.
- 조사는 스프레드시트로 하고, 확정된 것만 SQL로 옮기는 흐름을 추천합니다.

### 3. H2 제거, 로컬도 MySQL(Docker)
- H2와 MySQL은 SQL 방언과 동작이 조금씩 달라서 "로컬에선 되는데 서버에선 안 되는" 문제가 생깁니다. 혼자 디버깅하는 사이드 프로젝트에서는 이 시간이 아깝습니다.
- `docker compose up` 한 번으로 로컬 MySQL을 띄우면 운영과 같은 환경이 됩니다.
- 거리 계산(F-09)은 성지가 적어서 앱에서 계산하면 되므로 PostGIS 같은 공간 DB도 필요 없습니다. MySQL로 충분합니다.

### 4. 배포는 EC2 1대 + Docker Compose로 최소화
- 3단계 완료 기준은 "공개 주소의 API로 앱 동작"이라 서버 1대면 충분합니다. 로드밸런서, ECS, 쿠버네티스는 필요 없습니다.
- HTTPS는 필요합니다 (iOS는 기본적으로 HTTP 통신을 막습니다). 도메인 + Caddy 또는 Nginx + Let's Encrypt 조합이 가장 간단합니다.
- **비용 주의**: RDS는 계정의 무료 혜택 조건에 따라 매달 비용이 나올 수 있습니다. 혜택이 없거나 끝나면 EC2 안의 MySQL 컨테이너로 운영하다가, 실제 사용자가 생기면 RDS로 옮겨도 됩니다. 어느 쪽이든 AWS 예산 알림은 꼭 설정하세요.

### 5. 로그인 없는 후기(F-08)에 최소한의 방어
- 로그인이 없으면 누구나 후기를 쓸 수 있어서 스팸이 들어올 수 있습니다.
- 서버에서 입력값 검증(PRD 9번), IP당 작성 횟수 제한, REVIEW에 숨김 여부 컬럼(`hidden` 등) 하나 정도만 추가하면 됩니다.

### 6. 다국어 구조는 처음부터
- F-13(다국어)은 P3지만, 영어 우선 + 한국어 병기라 1단계부터 화면 문구를 i18next 키로 빼 두면 나중에 언어 추가가 파일 하나 추가로 끝납니다. 처음부터 하는 비용은 거의 없고, 나중에 하면 모든 화면을 다시 고쳐야 합니다.

### 7. 영상·장면 시점(F-19, F-20)은 링크로 시작
- 공식 YouTube 링크에 시작 시점(`?t=10`)을 붙여 `Linking`으로 열면 F-20까지 해결됩니다. 앱 안 재생이 필요 없어서 팀 질문 7번은 **"MVP는 링크로 열기"를 추천**합니다.
- 나중에 앱 안 재생이 필요하면 YouTube 공식 iframe 임베드(react-native-youtube-iframe 등)를 쓰면 됩니다.

## 단계별로 실제 쓰게 되는 것

| 단계 | 쓰는 기술 | 하지 않는 것 |
|---|---|---|
| 1단계 (앱만) | Expo, Expo Router, react-native-maps, AsyncStorage, i18next, 내장 JSON | 서버, DB |
| 2단계 (백엔드) | Spring Boot, JPA, Flyway, 로컬 MySQL(Docker), TanStack Query | 로그인, 관리자 화면 |
| 3단계 (AWS) | EC2 + Docker Compose, HTTPS, (RDS 또는 MySQL 컨테이너), 예산 알림 | 오토스케일링, 쿠버네티스 |
| 4단계 (확장) | 로그인(이때 저장·스탬프를 서버로 이전), S3(사진 후기), 오프라인 캐시 강화 | — |

## 정리: 사이드 프로젝트 기준 우선순위
1. 1단계는 서버 없이 앱만으로 끝까지 완성해서 친구들에게 먼저 보여주기
2. 기술보다 성지 데이터 20곳의 조사·검증에 시간을 더 쓰기
3. 새 기술은 꼭 필요한 곳에만 (위 추천 중 새로 배울 것은 Expo 관련과 Flyway 정도)
